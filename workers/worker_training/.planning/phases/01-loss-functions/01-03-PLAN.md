# Plan 3: Implement SubjectAdversarialLoss

## Objective
Implement the `SubjectAdversarialLoss` class in `src/training/losses.py` so all `TestSubjectAdversarialLoss` tests pass.

## Context
`GradientReversalFunction` is already fully implemented in the stub — do NOT modify it. Only `SubjectAdversarialLoss.__init__` and `SubjectAdversarialLoss.forward` need implementation.

The adversarial pattern:
- Forward pass: `shared_emb` passes through GRL (identity), then a small MLP subject classifier, then cross-entropy against `subject_ids`
- Backward pass: GRL negates and scales gradient by `alpha`, so the encoder is trained to REMOVE subject-discriminating information

Key test constraints from `tests/test_losses.py`:
- Output is scalar
- Loss is positive (cross-entropy is always >= 0, typically > 0 for random init)
- `emb.grad` is not None and all values are finite after `loss.backward()`
- `alpha=0.0` → `emb.grad` is all zeros (GRL passes `-0.0 * grad = 0`)
- The test does NOT check that gradients are negated vs. classifier gradients — only that they exist and are finite

Architecture: `embed_dim → hidden_dim → n_subjects` with ReLU in between.

### Task 2: Implement SubjectAdversarialLoss.forward
**Action:** Replace `raise NotImplementedError` in `SubjectAdversarialLoss.forward`.
**File:** `src/training/losses.py`
**Details:**
1. Apply GRL: `reversed_emb = GradientReversalFunction.apply(shared_emb, alpha)`
2. Get logits: `logits = self.classifier(reversed_emb)`  — shape `(batch, n_subjects)`
3. Return: `F.cross_entropy(logits, subject_ids)`
- `subject_ids` is a long tensor — `F.cross_entropy` expects class indices, so pass directly
- The alpha=0 test works because GRL backward returns `-0.0 * grad_output` which is a zero tensor
